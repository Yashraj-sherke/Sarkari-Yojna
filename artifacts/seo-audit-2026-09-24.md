# SEO audit — Sarkari Yojana Setu

Repository audit completed before implementation, 24 September 2026. Scope: App Router entry points, shared directory/detail components, scheme data access and editorial policy, sitemap/robots, image handling, identity and relevant tests. No dependencies or deployment changes planned.

## Critical
No confirmed site-wide indexing block in repository. Production fetch through the research browser failed; this does not establish an outage. Live HTTP, redirect, rendered HTML and Search Console verification remain required.

## High
1. Directory pagination uses buttons and renders only nine links; deeper records lack a reliable crawlable listing path. Add a visible server-rendered reviewed-scheme directory within each relevant listing, preserving interactive cards.
2. `allSchemes` and `getScheme` apply freshness differently; the fallback detail path mutates seed records. Sitemap/listing eligibility can disagree with detail noindex. Normalize enriched records consistently without mutation, reuse a single public-indexing predicate and preserve existing review restrictions.
3. Directory summaries discard editorial provenance; ACTIVE drafts can appear in a verified filter. Carry review status into summaries and distinguish reviewed records from drafts.
4. Scheme pages describe the independent publisher's pages as GovernmentService. Replace with factual Article markup, retain matching BreadcrumbList; do not invent author or publication dates.

## Medium
1. State/category pages reuse the homepage H1 and generic breadcrumbs. Give them contextual titles and matching navigation; include category in scheme breadcrumbs.
2. Root canonical and Twitter title defaults can leak homepage identity into missing or child routes. Scope the homepage canonical to the homepage, allow page Open Graph values to supply Twitter text, and complete sharing-image defaults on public collections/guides.
3. Scheme pages have no related document-guide links. Link existing general guides only when relevant to listed documents; avoid implying those guides are official application instructions.
4. Multiple card images are eagerly prioritized; detail image sizes underestimate its mobile/tablet width. Limit preloading to intended above-fold images and use layout-specific sizes.
5. Locally generated/category artwork is labeled official in alt text without demonstrated provenance. Use descriptive scheme/category labels.
6. Sitemap dates substitute unrelated information-page dates when source dates are absent. Omit unknown timestamps; use real content modification/review dates.
7. Static application mode labels use buttons without actions. Use headings instead.

## Low
1. Shared site-name constants omit Setu. Align text identity with requested brand.
2. Inherited social defaults and invalid state metadata need consistency checks.
3. Existing skip links, focus styles, image dimensions, Hindi lang, independent-site notices, official links, private-page noindex and sitemap exclusions are useful and should be retained.

## Content and operational risks
The catalogue contains 153 seeded records, with editorial review gates and incomplete drafts. Important reviewed articles already have benefits, eligibility, exclusions, documents, process, FAQs, sources and verification dates. This SEO pass must not fabricate refreshed verification dates or expand unverified scheme claims. Remaining drafts, duplicate scheme identities, official artwork provenance, thin generic guides and scheme-specific status/e-KYC/DBT details need source-by-source editorial review. Do not index drafts merely to increase page count.

Production uses a Vinext/Cloudflare path as well as Next.js; test both builds if available. No field LCP/INP/CLS baseline, Search Console access or Rich Results Test result has been obtained. Do not claim numerical performance gains, rankings or traffic.

## Validation and implementation
Implemented locally; no deployment performed.

- Shared indexability checks now govern scheme metadata, sitemap, category/state eligibility, related schemes and a visible server-rendered reviewed-scheme index. Seed and database reads normalize review freshness consistently without mutating seeds.
- Editorial provenance now survives directory summaries. Draft cards are labelled as needing verification and do not present unreviewed benefits/documents as current.
- Removed maintenance writes from listing reads; existing maintenance entry point in reminders remains. This avoids cleanup queries during builds/public listing requests.
- Homepage canonical is scoped to the homepage. Invalid dynamic metadata calls notFound. Category/state headings and visible breadcrumbs now describe their route; scheme breadcrumb JSON-LD matches the category path.
- Replaced GovernmentService with Article for reviewed informational content. Kept truthful WebSite/Organization/BreadcrumbList. Did not add unsupported FAQ rich-result claims, fabricated authors or publication dates.
- Added document-guide links based on actual listed documents, plus the existing application safety guide. Verification dates and scheme facts were not refreshed or invented.
- Removed unrelated timestamp fallbacks, including information-page dates on undated guides. Public guide/collection Open Graph images and shared Setu identity are consistent.
- Directory card images now lazy-load; scheme heroes retain priority and better responsive sizes. Footer icon images lazy-load with dimensions retained. Alt text no longer asserts generated artwork is official. No numerical CWV improvement has been measured.
- Replaced inert application-mode buttons with headings. Header uses usePathname instead of effect-driven path state, removing an extra render and tracking client navigation correctly.
- Repaired the pre-existing ESLint FlatCompat crash using the installed Next.js flat configuration. No dependencies added.
