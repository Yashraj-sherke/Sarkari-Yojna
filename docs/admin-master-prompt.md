Inspect repository instructions, the current package configuration, both Next.js and Vinext/Cloudflare runtimes, Neon PostgreSQL/Drizzle schema, admin routes, authentication, caches and public content rendering before changing code. Report confirmed implementation, partial functionality and unavailable integrations. Preserve existing user changes, public URLs and intentional admin noindex rules.

The repository's `lib/domain.ts` Scheme contract is authoritative. Preserve all canonical fields, eligibility `rules`, legacy `steps`, source references, actual verification dates, review scheduling, Hindi/English content, SEO fields and nested object structures. Strictly validate imports at every nesting level. Do not silently discard unknown fields or create a separate incompatible scheme representation.

Implement a working Hindi administration interface with real database metrics, SQL search/filter/sort/pagination, sectioned complete scheme editing, reorderable nested lists, source references, structured eligibility rules, translations, unsaved preview through public rendering components, JSON import/export, explicit conflict/diff confirmation, revision history and restore to working drafts. Make mobile layouts, labels, keyboard focus, errors, busy states and unsaved navigation warnings usable.

Implement secure server-managed authentication compatible with the actual deployment. Use salted password derivation and hashed random sessions if local accounts are required. Reject legacy weak hashes until deliberately reset. Optional provider identity headers are trusted only behind an explicitly configured proxy that strips client-supplied headers. Never trust a browser-provided identity header. Check permissions on every protected API and server data path; hiding buttons is insufficient.

Roles: Super Admin manages users/settings and publishes; Editor creates/edits/imports/exports/submits; Reviewer records source-based decisions and returns corrections. Reviewer publishing is denied unless explicitly implemented and granted. Protect self-demotion and the last active Super Admin. Revoking permissions or resetting credentials invalidates access. Do not ship a default production password, fake authentication, fake statistics or fake AI success.

Separate working drafts from published revisions. Draft save/import never alters an existing live article, marks verification complete or refreshes verification dates. Review requires dated authoritative references, claim traceability, all relevant factual checks including the scheme's actual operating status, substantive evidence notes and actual actor/time. Conflicts or unavailable authoritative facts remain unverified; never fabricate scheme amounts, dates, documents, eligibility, status or official links.

Publish only an explicitly approved unchanged revision. Later edits invalidate approval. Handle concurrent edits with version conflicts, and bind reviewed evidence to the exact content version. Persist mutation, history and publishing effects atomically. Archive preserves established scheme URLs with archived presentation; explicit unpublish is a separate confirmed action. Do not introduce permanent or bulk destructive deletion.

Manage scheme-related news through equivalent draft/review/publish controls with official source, date, what changed, affected citizens and links to actual scheme records. Existing static fallback content must not resurrect explicitly unpublished database news. Keep private research/review/user/session data out of public pages, exports where unrelated, and logs.

Treat imported content as untrusted. Sanitize rendered HTML, validate URLs, restrict executable links, enforce JSON size limits, same-origin mutation checks, login/sensitive-action rate limits and safe error messages. If official-domain restrictions are configurable, apply them on the server before approval/publication; URL response success is never a factual check.

Implement in phases: security/integrity; schema/editor/import/export; review/publication/revisions; dashboard/users/news/settings; isolated validation/documentation. For each phase record issue, change, actual tests and remaining setup. Test real SQL using an isolated database without touching production. Test unauthorized access, spoofed identities, role escalation, malformed/unknown import data, concurrency, revision integrity, review evidence, public-cache invalidation, news unpublishing, user/session revocation and XSS.

Run repository lint, unit/security tests, TypeScript and both production build targets. Fix failures caused by the implementation. Report only checks actually executed; distinguish local implementation from production rollout and Google outcomes. A dependency/security audit with unresolved advisories is a documented release limitation, not a clean production certification.

Provide additive migrations, placeholder configuration, PowerShell-compatible setup/test/build commands, secure initial administrator provisioning, backup/recovery instructions and explicit unavailable integrations.
